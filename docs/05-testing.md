# 测试

## 测试策略

测试应覆盖行为和风险，尤其是：

- API 成功路径。
- 请求校验失败。
- 未登录、无效 token、权限不足。
- 用户数据隔离。
- 数据库约束和事务行为。
- 第三方服务失败。

## 命令

```bash
uv run pytest
```

## 测试结构

- `tests/` 存放 API、service、integration 和配置测试。
- 涉及数据库的测试应使用独立测试数据，避免依赖固定生产数据。
- 涉及外部服务的测试必须 mock。

## 重写期注意

旧测试仍可能引用已删除的 `app.*` 模块。重写 `app/` 时应同步恢复或重写测试基线。

## 完成前检查

- 是否运行了最相关测试？
- 如果无法运行，是否说明原因？
- 是否新增了行为变化对应的测试？
- 是否需要更新 feature plan 或项目状态？
